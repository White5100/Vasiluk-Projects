1. Атрибуты HTML5-валидации: Использованы атрибуты: required (делает поле обязательным), minlength/maxlength (задают рамки количества символов), pattern (задает регулярное выражение проверки) и специализированные типы type (email, tel, date). Они обеспечивают мгновенную встроенную проверку силами браузера без JS.
2. Novalidate против JS: Атрибут novalidate отключает стандартные всплывающие подсказки браузера при ошибках, позволяя создать кастомный интерфейс ошибок. Отключение через JS убирает логику программной проверки, тогда как с novalidate браузер всё равно собирает объект ValidityState.
3. Связывание label и input: Реализуется через совпадение атрибута for у тега <label> с атрибутом id у тега <input>. Это критично для доступности (скринридеры озвучивают имя поля при фокусе) и UX (клик по тексту активирует поле).
4. Типы input под разные данные: Для почты — type="email" (вызывает собачку на мобильной клавиатуре), для телефона — type="tel" (цифровая клавиатура), для пароля — type="password" (маскирует символы), для даты — type="date" (встроенный календарь).
5. Атрибут pattern: Проверяет значение поля на соответствие регулярному выражению. Его следует использовать для специфических форматов данных, не поддерживаемых браузером по умолчанию (например, сложные пароли, маски телефонов или индексы).
6. События JS для валидации: blur (потеря фокуса) — чтобы проверить поле, когда пользователь закончил ввод, и input (изменение текста) — для мгновенного удаления сообщения об ошибке при начале исправления.
7. Доступность ошибок: Для скринридеров сообщения об ошибках связывают с полями с помощью ARIA-атрибутов (например, aria-describedby), либо динамически выводят текст в контейнеры со свойством aria-live="assertive".
8. Преимущества fieldset и legend: Семантически объединяют связанные по смыслу элементы управления (группа личных данных, группа паролей). Помогают скринридерам зачитывать контекст группы перед озвучиванием конкретного лейбла.
9. Кастомная валидация: Реализуется через JS на событии отправки формы или ввода. Сравниваются значения полей (password.value === confirmPassword.value) и при несовпадении метод setCustomValidity() или кастомные стили маркируют поле как невалидное.
10. CSS методы отображения валидности: Использование псевдоклассов :valid, :invalid, :focus, а также динамическое добавление JS-классов ошибок (например, .error), которые переопределяют border-color, background-color и вызывают анимации shake.
