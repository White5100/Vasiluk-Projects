1. В чем разница между event.preventDefault() и event.stopPropagation()? В каких ситуациях используется каждый метод?

`event.preventDefault()` отменяет стандартное действие браузера, которое происходит при событии. Например, с его помощью можно отменить переход по ссылке или отправку формы.
`event.stopPropagation()` останавливает распространение события по DOM. Например, если событие произошло во вложенном элементе, с помощью этого метода можно не дать ему распространяться дальше к родительским элементам.
Таким образом, `preventDefault()` влияет на стандартное действие браузера, а `stopPropagation()` - на распространение события между элементами.


2. Как работает делегирование событий и какие преимущества оно дает по сравнению с назначением обработчиков на отдельные элементы?

Делегирование событий заключается в том, что обработчик устанавливается не на каждый дочерний элемент отдельно, а на их общего родителя.
Событие от дочернего элемента всплывает к родительскому элементу. В обработчике можно определить, по какому элементу был выполнен клик, используя `event.target` или метод `closest()`.
Преимущество такого подхода в том, что не нужно создавать много одинаковых обработчиков. Кроме того, новые элементы, добавленные в список после загрузки страницы, тоже будут автоматически обрабатываться через родительский элемент.


3. Какие фазы жизненного цикла события существуют в JavaScript (capturing, target, bubbling) и как они влияют на порядок выполнения обработчиков?

У события есть три основные фазы:
1. `capturing` - событие проходит от верхнего элемента документа к элементу, на котором произошло действие.
2. `target` - событие достигает элемента, на котором произошло действие.
3. `bubbling` - событие распространяется обратно от дочернего элемента к родительским.
Например, при клике на кнопку событие сначала проходит через родительские элементы в фазе capturing, затем достигает кнопки, а после этого при bubbling снова проходит через родителей.
Благодаря bubbling работает делегирование событий.

4. В чем разница между event.target и event.currentTarget? Когда следует использовать каждый из них?

`event.target` показывает конкретный элемент, на котором первоначально произошло событие.
`event.currentTarget` показывает элемент, на котором непосредственно установлен текущий обработчик события.
Например, если обработчик установлен на `#item-list`, а пользователь нажал на кнопку удаления внутри элемента списка, `event.target` будет указывать на кнопку удаления, а `event.currentTarget` - на `#item-list`.
`event.target` удобно использовать при делегировании событий, когда нужно определить, по какому дочернему элементу был выполнен клик.
`event.currentTarget` удобно использовать для работы с элементом, на котором установлен обработчик.


5. Как создать и запустить кастомное событие? Какие параметры можно передать в конструктор CustomEvent?

Кастомное событие можно создать с помощью конструктора `CustomEvent`.
Пример:

```javascript
const event = new CustomEvent('customAction', {
    detail: {
        message: 'Привет от кастомного события!'
    }
});

После создания событие можно запустить с помощью метода dispatchEvent():
document.dispatchEvent(event);
Для обработки такого события используется addEventListener():

document.addEventListener('customAction', (event) => {
    console.log(event.detail.message);
});

В объект параметров CustomEvent можно передать detail. В нем можно хранить дополнительные данные, которые затем доступны через event.detail.

Что такое debounce и throttle? В каких практических ситуациях их применение наиболее эффективно?

Debounce откладывает выполнение функции до тех пор, пока не пройдет заданное время после последнего вызова.

Например, debounce удобно использовать в поисковой строке. Пользователь быстро вводит текст, а запрос отправляется только после того, как он перестал печатать.

Throttle ограничивает частоту выполнения функции. Даже если событие происходит очень часто, функция будет выполняться не чаще заданного интервала.

Throttle удобно использовать для обработки частых событий, например scroll, mousemove или большого количества быстрых кликов.

Основное отличие заключается в том, что debounce ждет окончания серии событий, а throttle ограничивает частоту вызовов.

7. Какие методы существуют для удаления обработчиков событий и почему важно удалять ненужные обработчики?

Для удаления обработчика событий используется метод removeEventListener().
Например:

function handleClick() {
    console.log('Клик');
}

button.addEventListener('click', handleClick);
button.removeEventListener('click', handleClick);

Важно использовать ту же функцию, которая была передана при добавлении обработчика.
Удаление ненужных обработчиков позволяет уменьшить количество выполняемого кода, избежать повторных срабатываний и возможных утечек памяти. Это особенно важно в больших приложениях и при динамическом создании и удалении элементов.

8. Как обрабатывать ошибки загрузки ресурсов (изображений, скриптов) и какие события для этого используются?

Для обработки загрузки ресурсов используются специальные события.
Для успешной загрузки изображения можно использовать событие load.
Для обработки ошибки используется событие error.
Также существуют события, связанные с началом и завершением загрузки, например loadstart и loadend.
Пример:

const image = new Image();

image.addEventListener('load', () => {
    console.log('Изображение успешно загружено');
});

image.addEventListener('error', () => {
    console.log('Ошибка загрузки изображения');
});

image.src = 'https://picsum.photos/300/200';

Таким образом, программа может показать пользователю успешное состояние или сообщение об ошибке.

9. В чем разница между addEventListener и прямым назначением обработчиков через onclick, onkeydown и т.д.?

При использовании addEventListener() можно назначить несколько обработчиков одного типа событий на один элемент.
Например:

button.addEventListener('click', handler1);
button.addEventListener('click', handler2);

Оба обработчика смогут выполниться.
При прямом назначении:

button.onclick = handler1;

при повторном присваивании:

button.onclick = handler2;

старый обработчик будет заменен новым.
addEventListener() также позволяет отдельно удалять обработчики через removeEventListener() и дает больше возможностей для управления фазами распространения событий.
Поэтому для современной разработки чаще используется addEventListener().

10. Как оптимизировать производительность при работе с большим количеством событий? Какие лучшие практики существуют?

Для оптимизации обработки большого количества событий можно использовать несколько подходов.
Во-первых, применять делегирование событий вместо добавления одинаковых обработчиков на большое количество дочерних элементов.
Во-вторых, использовать debounce и throttle для событий, которые происходят очень часто, например scroll, mousemove или быстрых изменений ввода.
В-третьих, удалять обработчики, которые больше не нужны, с помощью removeEventListener().
Также желательно избегать выполнения тяжелых операций при каждом событии, уменьшать количество лишних изменений DOM и выполнять только необходимые действия.
Эти подходы позволяют уменьшить нагрузку на браузер и сделать интерфейс более отзывчивым.
